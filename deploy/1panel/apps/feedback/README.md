# 反馈墙 FeedbackWall（开源版）

自托管的用户反馈收集与管理系统。创建多个产品 / 项目，每个产品拥有独立的公开反馈页，
收集**建议 / 问题 / 吐槽 / 提问**，用投票和评论凝聚共识，用状态流转和看板闭环跟进。

## 首次使用

1. 安装完成后访问 `http://服务器IP:访问端口/#/login`（注意是 `#` 号路由）。
2. 用安装表单里填写的**管理员邮箱 / 管理员密码**登录；账号在首次启动时自动创建，部署完直接登录使用。
3. 登录后即可新建产品，公开反馈页地址为 `http://服务器IP:访问端口/#/p/{slug}`。
4. 建议在「账户设置」里修改密码，并在「产品设置」里配置 Logo、主题色和通知推送。

> 忘记密码：可在数据库用 bcrypt 生成新哈希写回 `users.password_hash`，详见仓库 README 的常见问题。

## 内置功能

- 反馈收集：分类、标签、附件（图片 / 视频）、联系方式
- 互动：投票、评论、官方回复、置顶 / 隐藏 / 私密
- 管理：状态流转（待处理 → 规划中 → 进行中 → 已解决…）、看板统计、CSV 导出
- 通知：邮件 SMTP、Webhook、钉钉 / 企业微信 / 飞书群机器人
- 开放能力：API 密钥、FAQ、更新日志、iframe / widget 嵌入组件
- 文件存储：本地磁盘（默认）、腾讯云 COS、阿里云 OSS

## 数据与端口

| 项 | 说明 |
| --- | --- |
| 访问端口 | 安装表单中的「访问端口」，默认 8081 |
| MySQL | 随应用一起安装，仅容器网络内可访问，数据卷 `./data/mysql` |
| 上传附件 | 数据卷 `./data/uploads` |
| 配置参数 | 1Panel 应用详情中可查看 / 修改表单参数 |

`./data` 为绑定挂载目录，卸载应用或执行 `docker compose down` 不会删除数据；
备份请同时保留 `./data/mysql` 与 `./data/uploads`。

## 注意事项

- 前端是 HashRouter（`#` 模式），刷新任意页面都不会 404；请勿把域名指向真实子路径。
- 通过 1Panel 反向代理绑定域名时，请把「对外访问地址」改成实际域名（如 `https://feedback.example.com`），
  否则邮件链接与图片地址的兜底域名会指向 `127.0.0.1`。
- 附件 URL 优先按请求进来的对外域名生成（反代透传 `Host` / `X-Forwarded-Host` 即可自动正确）。
- 后端允许任意来源跨域（CORS 反射 Origin），公开反馈页可嵌入第三方站点。
- 如需独立 API 域名，需要重新构建 web 镜像并注入 `VITE_API_BASE_URL`（该值在构建时写入静态资源）。
